# События проекта и audit log

Проект должен хранить историю важных действий. Нельзя тихо менять рабочий проект без следа.

## ProjectEvent

ProjectEvent — событие жизни проекта.

Примеры:

- проект создан;
- изменён клиент;
- изменена площадка;
- изменена дата;
- добавлен раздел;
- удалён раздел;
- изменена смета;
- отправлено КП;
- проект подтверждён;
- создан резерв склада;
- изменён складской лист;
- выдано оборудование;
- выполнен возврат;
- зафиксировано повреждение;
- создана задача;
- задача закрыта;
- добавлен комментарий;
- добавлен файл;
- проект закрыт;
- проект отменён.

## AuditLog

AuditLog фиксирует критические системные действия.

Примеры:

- изменение роли пользователя;
- выдача ключа доступа;
- отзыв ключа;
- изменение системных прав;
- изменение финансовых прав;
- корректировка складского остатка;
- снятие резерва;
- backend write;
- risk/checklist override;
- удаление проекта;
- изменение настроек;
- изменение категории ресурсов.

## Разница

ProjectEvent — история конкретного проекта.

AuditLog — системная история безопасности и критических действий.

Часть событий может попадать и туда, и туда. Например подтверждение проекта важно и как project event, и как audit event.

## Структура события

Событие должно хранить:

- `id`;
- `workspaceId`;
- `projectId`, если применимо;
- `type`;
- `actorUserId`;
- `createdAt`;
- `payload`;
- `before`;
- `after`;
- `visibility`;
- `relatedEntityType`;
- `relatedEntityId`.

## Версионирование изменений

Если действие меняет рабочий проект после подтверждения, система должна:

- записать событие;
- сохранить старое и новое значение;
- уведомить затронутые роли;
- при необходимости создать новую версию складского листа, КП или документа.

## Видимость событий

Не все события видны всем.

- Админ видит всё.
- Менеджер видит проектную историю.
- Склад видит складские события проекта.
- Техник видит события своих задач и разделов.
- Приглашённый специалист видит только события в пределах своего доступа.

## Неизменяемость

Критические события нельзя удалять обычным редактированием. Если нужно исправление, создаётся новое событие корректировки.

## Зачем это нужно

История нужна для:

- восстановления картины проекта;
- контроля ответственности;
- разрешения спорных ситуаций;
- работы склада;
- версии документов;
- безопасности;
- backend sync;
- будущей аналитики.
