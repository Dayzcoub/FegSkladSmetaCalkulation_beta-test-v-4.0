# Безопасность

Этот документ фиксирует базовые правила безопасности приложения.

## Secrets

Секреты нельзя хранить в Git.

Запрещено коммитить:

- пароли;
- private keys;
- service role keys;
- database URLs с паролями;
- push private keys;
- SMTP passwords;
- production tokens.

В репозитории допускается только `.env.example` без реальных секретов.

## Frontend limitations

Frontend не должен иметь service role key или другие ключи, позволяющие обойти безопасность backend.

Опасные операции должны идти через controlled backend path.

## Access control

Доступ строится по модели:

```text
base profile + system permissions + project assignments + access keys + expiration
```

Приглашённые пользователи видят только то, что нужно для их проекта и задачи.

## Financial data

Финансовые данные нужно ограничивать:

- себестоимость;
- маржа;
- закупочные цены;
- субарендная цена;
- скидки;
- финансовые отчёты.

Технические роли не видят финансовую кухню по умолчанию.

## File access

Файлы проекта, фото площадок, документы, PDF и 3D-ассеты не должны быть публичными без контроля.

Нужны:

- workspace scope;
- project scope;
- signed URLs или аналогичный механизм;
- срок действия ссылок;
- audit для чувствительных документов.

## Demo/test data

Demo/test fixtures не должны загружаться в production entry.

Test users, invite keys and fixtures должны быть ограничены dev/demo окружением.

## Audit

Критические действия должны логироваться:

- входы и восстановление доступа;
- смена прав;
- выдача ключей;
- подтверждение проекта;
- складские резервы;
- изменения остатков;
- backend writes;
- рискованные overrides;
- удаление или архивирование данных.

## Backups

Backup должен храниться безопасно и отдельно от production data, если возможно.

Backup тоже содержит чувствительные данные и должен защищаться.

## Public links

Публичные ссылки должны быть ограничены:

- по сроку;
- по правам;
- по проекту;
- с возможностью отзыва.

## Principle

Безопасность должна быть встроена в архитектуру, а не добавляться после. Особенно это важно для файлов, финансов, складских операций, access keys, backend writes and invited specialists.
