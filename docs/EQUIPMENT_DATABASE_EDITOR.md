# Equipment Database Editor

Версия: v3.10.6

Этот слой добавляет в локальную базу оборудования полноценный редактор позиций и автоматическую генерацию кодов по выбранной категории.

## Что изменилось

- В разделе «База оборудования» есть кнопка **Добавить позицию**.
- В строках таблицы и в мобильных карточках есть кнопка **Редактировать**.
- Редактирование открывается во всплывающей карточке, не ломая текущий список и фильтры.
- При создании новой позиции код создаётся автоматически по категории.
- При смене категории в новой карточке код пересчитывается автоматически, пока пользователь не поправил код вручную.
- В карточке есть кнопка **Сгенерировать**, чтобы пересоздать код вручную.

## Правило кодов

Код состоит из трёхбуквенного префикса категории и порядкового номера:

```text
STG-001
TRS-001
LED-001
SND-001
```

Текущие префиксы:

| Категория | Префикс |
|---|---:|
| Сцены | STG |
| Фермы | TRS |
| LED | LED |
| Свет | LGT |
| Звук ПА | SND |
| Пульты | MIX |
| Мониторинг | MON |
| Бэклайн | BKL |
| Расходники | CNS |
| Услуги | SRV |
| Коммутация | COM |

Следующий номер ищется по уже существующим кодам этой категории. Например, если есть `LED-001` и `LED-002`, новая LED-позиция получит `LED-003`.

## Поля карточки

Карточка поддерживает:

- код;
- название;
- категорию;
- подкатегорию;
- тип;
- единицу измерения;
- производителя;
- модель;
- количество на складе;
- резерв;
- вес;
- рабочую мощность;
- пусковую мощность;
- прокатную цену;
- стоимость замены;
- источник: свой склад / субаренда / ручная позиция;
- поставщика;
- комментарий;
- активность позиции.

## Безопасность

- Изменения сохраняются только локально через `EquipmentDatabase.upsertItem()`.
- Backend-запись не включается автоматически.
- Проверяется наличие названия, кода и отсутствие дубля кода.
- Резерв не может быть больше количества на складе.
- Автогенерация не перезаписывает вручную изменённый код.

## Будущий Supabase

Сохранённые позиции уже нормализуются под структуру будущей таблицы `equipment_items` и попадут в staged payload через существующий `EquipmentServerSyncQueue`.


## v3.10.7 — исправление генерации кода

Кнопка «Сгенерировать» в карточке позиции принудительно вызывает `EquipmentDatabase.generateNextCode(category)` по выбранной категории. Для работы UI `EquipmentDatabase` экспортирует `generateNextCode()` и `getCategoryCodePrefix()`.


## v3.10.8 — единая серия кодов

Каталог оборудования приведён к единой схеме: три буквы категории + номер, например `STG-001`, `TRS-001`, `LED-001`, `SND-001`, `MIX-001`, `BKL-001`, `LGT-001`, `COM-001`. Старые коды сохраняются в `meta.legacyCode` и `meta.legacyCodes`, поэтому поиск и сопоставление складских строк по старым кодам продолжает работать.

Для существующей локальной базы добавлена кнопка **«Привести коды»**. Она пересобирает коды всех позиций по категориям, сохраняет старые значения как legacy-коды и записывает результат обратно в localStorage.

## v3.10.9 legacy search note

Поиск в UI базы оборудования должен учитывать не только текущий `code`, но и старые коды из `meta.legacyCode` / `meta.legacyCodes`. Это нужно для безопасного перехода от Excel/demo-кодов к новой схеме `STG/TRS/LED/...` без потери совместимости складских листов и старых привычных обозначений.


## v3.11.0 category normalization note

В редактор базы добавлен диагностический блок «Нормализация категорий» и экспорт `Категории JSON`. Категории, пришедшие из Excel или ручного ввода как `звук`, `свет`, `кабели`, `услуги` и т.п., приводятся к стабильным `category id`, а исходное значение сохраняется в `meta.originalCategory`.


## v3.11.1 — типы и sync schema

В редакторе база использует `ITEM_TYPE_DEFINITIONS`: типы показываются с понятными названиями, для новой позиции подставляется тип по категории, а кнопка `Sync schema JSON` выводит `buildSyncSchemaReport()` с sample row для будущей таблицы `equipment_items`.


## v3.11.2 — Supabase sync preview

В базе оборудования добавлен блок `Supabase sync preview` и кнопка `Sync preview JSON`. Это позволяет проверить, как позиции будут выглядеть в таблице `equipment_items`, до включения реальной записи на backend.


## v3.11.3 — Safe cleanup

В редакторе базы оборудования появился `Sync readiness checklist`, кнопка `Readiness JSON` и безопасная кнопка `Safe cleanup`. Safe cleanup не выдумывает реальные данные и не меняет складские остатки автоматически.


## v3.12.0 — Manual completion matrix и patch workflow

В базе оборудования появился блок `Manual completion matrix`, фильтр `Добивка`, быстрые фильтры по задачам и JSON workflow `Patch template` / `Import patch`. Импорт принимает только поля ручной добивки и не выполняет складские движения.
