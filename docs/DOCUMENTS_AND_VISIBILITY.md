# Документы и правила видимости

Документы должны строиться из проект-сметы и её snapshot/version data, а не из случайного состояния интерфейса.

## Типы документов

- клиентское КП;
- внутренний технический лист;
- складской лист сборки;
- лист дефицита;
- лист субаренды;
- чек-лист площадки;
- задачи команды;
- календарное событие;
- акт выдачи;
- акт возврата;
- фотоотчёт;
- export JSON/HTML/PDF.

## Клиентские документы

Клиентские документы должны показывать только то, что предназначено клиенту:

- понятные названия;
- количество;
- цену;
- итог;
- условия;
- сроки;
- комментарии.

Не должны показываться без явного решения:

- себестоимость;
- маржа;
- внутренние закупочные цены;
- складская кухня;
- внутренние коды, если они не нужны клиенту;
- персональные данные команды;
- внутренние риски.

## Внутренние документы

Внутренние документы могут содержать:

- технические параметры;
- схемы;
- веса;
- мощность;
- кабели;
- нагрузки;
- риски;
- дефицит;
- субаренду;
- комментарии команды.

## Складские документы

Складские документы должны показывать:

- код;
- позицию;
- количество;
- раздел проекта;
- own / deficit / subrent;
- складской статус;
- место хранения, если есть;
- вес/габариты;
- комментарии.

Клиентские цены и маржа складу не нужны по умолчанию.

## Документы по ролям

### Менеджер

Видит КП, внутреннюю смету, дефицит, субаренду, документы клиента и проектные документы.

### Техдир

Видит техлисты, чек-лист площадки, риски, фото, схемы и задачи технической команды.

### Склад

Видит складские листы, выдачу, возврат, дефицит и комментарии по сборке.

### Технические роли

Видят техлисты и документы своих разделов.

### Приглашённый специалист

Видит только документы, нужные для его проектной роли.

### Админ

Видит всё.

## Snapshot rule

Отправленные и подтверждённые документы должны храниться как snapshot. Нельзя полагаться только на текущую проектную модель, потому что она может измениться после отправки.

## Version rule

Документ должен иметь:

- тип;
- версию;
- статус;
- snapshot;
- видимость;
- автора;
- дату создания.

## Export rule

PDF/HTML/JSON export должен строиться из нормализованных данных проекта, а не из случайного DOM. Исключение — визуальные схемы, но и они должны быть привязаны к project/section model.
